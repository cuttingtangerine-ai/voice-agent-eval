# 02｜项目方案、场景与评分标准

项目方案与测试表 · v0.1 · 2026-10-19

> 本文件为 v0.1 方案原文，实测按此版本执行。实测结果见 [03-results-and-analysis.md](03-results-and-analysis.md)；实际执行规模为一轮 16 段，与下文“建议范围”不同。

## 1. 项目定位与已定范围

这个项目从日常语音对话里的几个具体体验切入：有没有听准，用户插话时怎样处理，说话是否自然。目标是把使用观察转化成可执行、可复查的评测案例，用于申请语音／Agent评测相关岗位。

已确定：

- 测试对象：用户可以使用的ChatGPT和豆包实时语音通话功能。
- 预算约束：使用现有账户与可用额度，零新增付费；本轮不纳入需额外购买的服务。
- 保留三个观察维度：准确性、打断处理、语气感知与语音自然度。
- 最终展示设计、执行记录、问题分析和改进建议；实际结果等待测试。

建议范围，待试跑后确认：

- 先试跑C01、C04、C05，每款一次，共6段测试，检查话术与录音是否可用。
- 正式版8个场景，每款各执行2轮，共32段测试；探索性样本，不用于产品整体排名。
- 试跑不混入正式统计。若修改话术或评分标准，记录版本，再按新版本执行正式测试。

## 2. 测试边界

测试对象是用户可接触的整体产品。最终回答出错，可能涉及收音、识别、理解或对话管理；没有内部数据时，不直接归因为某个技术模块。

“逐字识别准确率”只在产品提供可核查转录且记录完整时讨论。本项目优先检查最终回答是否保留关键信息。转录不可见时填写“不可观测”，不从最终回答反推完整识别结果。

语气感知只作探索性观察。语速快、停顿多并不能单独证明用户处于某种情绪；不把“猜中情绪标签”设为当前核心指标。

## 3. 执行与证据

- 尽量使用同一手机、同一耳机或扬声器、相近收音距离、同一网络环境。
- 每个场景开独立新对话。无法隔离的历史记忆、个性化设置如实记录。
- 两款产品保留各自选定音色，记录名称；本轮不评音色偏好。基础语速设置尽量相近，无法统一则说明。
- 记录实际测试日期、时间、App版本、语音模式、可见模型名称、账户档位。看不到的信息写“未显示”，不猜测底层模型。
- 第一轮先测A后测B，第二轮交换顺序，减轻顺序和网络时段差异。
- 先验证录屏是否同时收录用户与产品声音。不能完整录音时保留原话与即时笔记；没有音频证据就不报告精确延迟。
- 通话中断、网络卡顿、用户插话时机明显偏离脚本等单列“执行异常”，保留原记录；补测另建编号。

## 4. 场景脚本

涉及人名均为测试用虚构名称。每个场景只评价列出的项目。

| 编号 | 场景与执行话术 | 观察重点 |
| --- | --- | --- |
| C01 | 说：“帮我复述这条安排：周五下午三点半，两个人，在西门见，预算一百五十元。” | 四个信息槽：周五15:30、2人、西门、150元。记录正确数／4、遗漏、替换、无依据添加。 |
| C02 | 先说：“我朋友叫林溪，树林的林，溪水的溪。请记住这个名字。”等回应后说：“林溪想做一个语音评测项目，请用一句话复述她想做什么。” | 后续能否正确沿用名字和任务。有转录则记录文字；音频无法区分同音字时，该字形项记不可观测。 |
| C03 | 先说：“请给我讲三个整理书桌的小方法。”产品进入第一点后轻咳一声，不说话。 | 是否因非语言声音停下、转题或追问。记录行为，不预设任何短暂停顿都是失败。 |
| C04 | 使用同样的书桌任务。产品进入第一点后，以轻声附和语气说“嗯嗯”，不补充其他话。 | 是否保留原任务并继续，是否把附和当成新请求。允许自然短回应，不要求必须说语气词。 |
| C05 | 先说：“我明天下午三点开会，请帮我安排会前准备，分三点说。”进入第一点后正常音量插话：“等一下，改成两点，不是三点。” | 能否停止原输出，处理新信息，并按两点继续。分别记录是否停下、是否更新、是否再次使用旧时间。 |
| C06 | 使用同样的会前准备任务。进入第一点后插话：“先不聊这个了。现在只帮我把‘请明天回复’翻译成英文。” | 能否切换到新任务，是否仍继续安排会议。翻译允许自然等义表达。 |
| C07 | 说：“我想做一个……”停顿约1.5秒，再接“语音评测项目，请先帮我想一个标题。” | 是否在话未完成时抢答，后半句出现后能否接上任务。1.5秒是本轮刺激条件，不是通用产品门槛；保留实际停顿长度或估计值。 |
| C08 | 说：“请用三句话，向第一次接触这个概念的人解释什么是语音识别。说慢一点，在句子之间留一点停顿。” | 内容是否易懂、语速与句间停顿是否符合请求，有无异常重音或断句。内容遵循与声音自然度分别记录。 |

如果C03或C04明显无法稳定复现刺激声音，先调整执行方法，固定后再进入正式测试。不要把试验者失误算成产品缺陷。

## 5. 评分规则草案

采用1—5分：下表给出1、3、5分锚点；介于相邻锚点时可记2或4，须解释。不可观测填N/O，不适用填N/A，均不记0分。

| 评价项 | 1分 | 3分 | 5分 |
| --- | --- | --- | --- |
| 关键信息保留（C01） | 四个信息槽仅正确0—1个 | 正确3个，存在一项遗漏或错误 | 四项全部正确，无改变任务含义的额外信息 |
| 上下文沿用（C02） | 忽略前文且无法正确复述任务 | 任务正确，但可观测的名称信息仍出错或需重复澄清 | 正确沿用可观测名称信息和任务，不需额外纠正 |
| 非语言声／附和处理（C03、C04分别评分） | 丢失任务，持续转题或无法继续 | 原任务保留，但不必要的追问或中断打乱交流，需要用户提示继续 | 保持任务连贯，继续或简短回应均自然 |
| 纠正处理（C05） | 未处理纠正，继续使用旧时间 | 接收到纠正，但仍混用新旧信息或需再次提醒 | 及时让出话轮，后续按新时间回应，不再混用 |
| 换题处理（C06） | 忽略新请求，继续旧任务 | 完成新任务，但仍明显夹带旧任务或需再次打断 | 让出话轮，直接处理新任务，旧任务不干扰 |
| 未完话语处理（C07） | 抢答后持续忽略补充，无法完成标题任务 | 有抢答，但听到补充后能修正并完成任务 | 等待话语完成，或短促接话后立即让出话轮，整体衔接顺畅 |
| 输出自然度（C08） | 频繁异常停顿、重音或语速变化，明显妨碍理解 | 内容可理解，但有明显念稿感或不合语意的断句 | 语速、重音、停顿与内容相符，听感流畅，无明显异常 |

补充记录：

- C01同时报告正确信息槽数，不只报主观分数。
- C05、C06的“及时”先记录实际停止表现；若音频可测，测量用户插话起点到产品停止原回答的时长。允许重叠发声，不将整段输出静音误记成停下。
- 回应等待时间另记为用户本轮说完到产品开始相关回应的时长。两类时间不要混为一谈。
- C08另记“三句话、解释对象、慢速及停顿请求”是否遵循，不与音质混写。
- 不因有无“嗯”“好的”等语气词单独加减分。
- 暂不将各项加权合并为一个总分，以免不同场景难度及主观听感掩盖具体问题。

## 7. 汇总与分析

逐场景汇总两轮结果，保留两次分数及差异。可描述“本场景两轮均出现”“仅一轮出现”，不把两轮结果当作稳定概率估计。主观评分优先保留原始分数与证据。

问题卡片模板：

1. 触发条件：在哪个脚本、哪一轮出现。
2. 可见行为：产品实际说了什么、何时停下。
3. 对交流的影响：是否需重复、纠正，是否偏离任务。
4. 暂定问题类别：信息遗漏、旧信息未更新、误判附和、抢答等；技术原因写成待验证假设。
5. 改进建议：针对该行为给出具体期待，不空泛写“提升智能”。
6. 验证办法：修复后重跑哪个场景，看哪个现象是否消失。

如能邀请第二位评价者，只提供音频、脚本和评分表，让其独立评分并记录分歧；做不到则如实说明仅单人评分，不写“已验证评分一致性”。

## 8. 求职展示结构

建议正文约4—6页，完整测试记录作附录：

1. 项目问题与个人观察起点。
2. 评测维度、评分锚点与场景设计。
3. 执行方法及样本边界。
4. 有证据的典型问题与产品差异。
5. 改进建议、方案局限与下一步。

## 9. 决策与下一步

尚待试跑确认：录音能否完整收声、可见转录范围、脚本时机、评分锚点是否覆盖真实情况、正式版最终规模。

下一步可逆实验：只做C01、C04、C05的六段试跑，先验证流程。试跑后修改本文件，再开始正式测试。
