# 01｜语音Agent评测执行SOP

## 用途与输入

用于执行并维护本项目的语音对话体验评测。每次开始先读取项目主页、当前场景与评分标准、测试记录，沿用最新方案版本；不要依靠旧聊天重建标准。

固定约束为现有账户、零新增付费。产品、版本、场景、轮次和证据为每次执行输入。没有真实通话或录音时，只准备脚本，不填写测试结果。

## 第一步：准备

1. 确认本次是试跑、正式还是补测；核对场景、产品、方案版本和记录编号。
2. 使用独立新对话，记录设备、收音方式、网络、App版本、音色与可见模式；无法读取的信息写“未显示”。
3. 先录一小段，回放确认用户和产品两路声音均可听清。若不支持完整录音，改用能保存双方声音的现有设备，或保留即时记录并标明证据局限。

## 第二步：试跑与冻结

1. 试跑C01、C04、C05，两款各一次。查脚本能否执行、插话时机是否明确、评分锚点能否使用。
2. 若修改脚本或评分标准，更新版本和修改理由，保留旧版快照。
3. 明确本轮采用版本后，再开始正式数据收集；试跑不混入正式汇总。

## 第三步：执行

1. 每个场景单独开新对话，按当前版本脚本说话。
2. 第一轮先测ChatGPT再测豆包，第二轮交换顺序；保持相近设备与收音条件。
3. 不满意的回答也保留。卡顿、断线和脚本偏离记为执行异常；补测另建编号，链接原记录。

## 第四步：记录与评分

1. 每执行一次新建或填写一条记录，不覆盖前一轮。
2. 写用户原话、产品原回应、证据编号与时间点，再按该场景评分锚点评分。
3. 主观判断要引用具体停顿、重音、回应内容或用户需要重复的位置。信息槽等客观检查单独列出。
4. 不可观测记N/O，不适用记N/A；分数留空，不记0。无完整音频不报告精确延迟。
5. 没有内部数据时只判断可见产品行为，技术原因作为待验证假设。

## 第五步：复核与分析

1. 回放关键片段，核对原话、分数和证据定位；两轮表现分别保留。
2. 按触发条件、可见行为、用户影响、问题类别、改进建议、验证办法整理问题卡片。
3. 如果只有单人评分就注明，不宣称验证过一致性；如有第二评价者，保存独立评分和分歧。
4. 结论限制在已测场景，不以小样本给出产品整体排名，不把两轮出现次数解释为稳定概率。

## 第六步：作品集与归档

1. 使用问题分析页的结构写4—6页案例，附场景、评分标准、原始记录和证据索引。
2. 简历只写已实际完成的规模和发现；未上线验证不写提升准确率或满意度。
3. 从项目主页导出可编辑快照，数据库检查完整行数与字段；另存录音原文件。
4. 作品集导出PDF后检查中文、表格、页面裁切和证据引用。保存版本与导出日期。

## 缺失输入与完成检查

- 没有录音或原回应：标为待补证据，不猜测评分。
- 脚本或评分规则冲突：先保留原记录，明确版本后再分析，必要时补测。
- 记录工具写入不可用：输出本次编号与完整记录文本，标明尚未同步，不声称已保存。
- 完成条件：脚本、评分、实测证据、问题分析和导出文件可相互对应。未达到时保持进行中。
