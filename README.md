# 🎙️ 语音Agent对话体验评测｜ChatGPT × 豆包

通过 ChatGPT 与豆包的实时语音通话，把“听准、接话、说得自然”转化成**可执行、可复查、有证据**的评测记录。

> **当前阶段：已完成一轮实测（8 个场景 × 2 款产品，共 16 段），发现 3 个典型问题。**
> 本轮为单人评分、每场景一轮的探索性样本，结论只说明本轮表现，不用于产品整体排名。

## 主要发现

| 问题 | 产品 | 场景 | 评分 |
| --- | --- | --- | --- |
| 用户已说明“溪水的溪”，回应复述了这句说明，写出的却是“林熙”，之后持续沿用错字 | ChatGPT | C02 上下文沿用 | 3 |
| 换题后只把“明天回复”译成 “tomorrow”，丢了“回复” | 豆包 | C06 换题处理 | 4 |
| 用户说“我想做一个……”后停顿约 2 秒就接话 | 豆包 | C07 未完话语 | 4 |

表现良好：两款产品都没有被附和“嗯嗯”打断（C04）；ChatGPT 在 3 秒停顿内一直等待（C07）。

完整分析、问题卡片与改进建议见 [`docs/03-results-and-analysis.md`](docs/03-results-and-analysis.md)。

## 项目概览

| 项目 | 内容 |
| --- | --- |
| 测试对象 | ChatGPT、豆包的实时语音通话功能（用户可接触的整体产品） |
| 评测维度 | 准确性、打断处理、语气感知与语音自然度（情绪推断仅作探索性观察） |
| 场景 | 8 个场景脚本（C01—C08），覆盖信息复述、上下文沿用、非语言声、附和、插话纠正、换题、未完话语、输出自然度 |
| 评分 | 1—5 分锚点评分；不可观测记 N/O，不适用记 N/A，均不记 0 分；不合并总分 |
| 实测规模 | 8 个场景 × 2 款产品 × 1 轮 = 16 段 |
| 记录方式 | 问题记录制：发现问题或值得记录的表现时填写，共 6 条；未记录的 10 段由执行者判定未发现问题 |
| 预算 | 使用现有账户与可用额度，零新增付费 |

## 设计亮点

- **评测边界清楚**：只判断可见产品行为。最终回答出错可能涉及收音、识别、理解或对话管理，没有内部数据时不直接归因于某个技术模块，技术原因写成待验证假设。
- **客观检查与主观评分分开**：例如 C01 同时报告“正确信息槽数／4”，不只给主观分数；C08 的“指令遵循”与“声音自然度”分别记录。
- **两类时间不混用**：区分“用户插话起点 → 产品停止原回答”的让出时长，与“用户说完 → 产品开始相关回应”的等待时长；没有完整音频不报告精确延迟。
- **控制顺序与环境差异**：第一轮先测 ChatGPT 后测豆包，第二轮交换顺序；每个场景开独立新对话，记录设备、网络、App 版本、音色等条件。
- **如实说明局限**：探索性小样本，不做产品整体排名；单人评分就注明单人评分，不宣称验证过评分一致性。

## 记录约定

- 一行是一款产品在一个场景的一次执行。
- 编号规则：`产品缩写-场景-轮次`。CG 表示 ChatGPT，DB 表示豆包；例如 `CG-C02-R1`。
- 补测另建编号，不覆盖原记录。
- 录音文件与记录使用同一编号，证据定位写明起止时间。
- 分数没有评过就留空。N/O 代表不可观测，N/A 代表不适用，均不记 0 分。
